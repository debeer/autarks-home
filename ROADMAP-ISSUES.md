# Draft roadmap issues

These are draft issues to open on the public repository later. They are planning notes, not a claim that the work is already funded or complete, except where that is stated.

## Finish the owner-facing interface so invited beta needs no command line

The lab prototype already onboards an owner and publishes drafts through the CMS. The remaining work before invited beta is principally a complete owner interface, after which the command line is no longer required.

## Add hardware-key and passkey authentication before invited beta

Hardware security keys and passkeys are planned before invited beta and are not built yet. They should remain a choice for the owner, not a requirement.

## Run an invited beta of the core appliance

Start an invited beta once the owner interface is complete and the planned authentication work is in place. The trial process is still being designed.

## Publish a design for a local AI peripheral

Produce a public design for an affordable local AI add-on, with inference and raw data kept in the home. This is proposed as Fellowship Q1 work, if that application is successful, and is not part of the pre-beta core appliance.

## Integrate the local AI engine, research applications, blueprint and benchmarks

If the Fellowship is funded: integrate the local AI engine; ship the first research-support applications; begin model-selection, quantisation and routing software; release an open buyer's blueprint; and complete compute-per-pound and per-watt benchmarks, including a comparison of pooling affordable boxes against one expensive machine. Proposed for Fellowship Q2–Q4.

## Open-source release with documented builds and owner-held keys

Publish the appliance software as open source (AGPL), with documented firmware and OS builds, and with keys and backups remaining in the owner's possession, so that if the company disappears, owners lose nothing. Early code will be released as it stabilises; a full release with documented builds is proposed for Fellowship Q3 if that application is successful.

## Exploratory federated adaptation test, and a public prototype

If the Fellowship is funded: run a modest, exploratory test of federated adaptation across mixed, intermittently connected home appliances, aiming for privacy guarantees explained in plain language, with raw data staying in the home; and ship a public prototype people can try, usable without buying an appliance. Proposed for Fellowship Q4.

## Design the guild management module (not grant-funded)

Every appliance is a standalone node and may join others as a guild node, with founders setting membership, governance and fees. The management module must still be designed and built. It is later work as a separate commercial product, not funded by the current grant applications.

## Design the data modeling module (not grant-funded)

A data modeling module is also planned: a general-purpose tool for designing and maintaining models of an owner's or a group's own data, in any subject, so that a local AI can work on it, with AI assisting in the modeling. It is later work, is not funded by any grant application, and will be a separate commercial product, outside the open-source commitment. It is an optional addition. The open appliance, the AI engine and the Research Workbench do not depend on it and are usable without it.
